# User guide and troubleshooting

Author: Jason Stys · [contact/issues](https://github.com/JasonStys/mission-verification-evidence-kit/issues).

Launch the portable app after verifying its checksum and fully extracting the archive. It opens a normal browser on a random loopback port; the process must stay open. There is no installer, account, analytics or automatic updater. Stop it by closing its console. A console window is expected; this is an unsigned portable application, not a signed OS-native installer. Respect OS security policies.

Choose **Evidence scenario** and **Maximum evidence age**, then **Evaluate baseline**. Editing controls immediately hides old evidence and downloads. The fixed fixture clock makes scenarios reproducible: it is not current live mission time. Green means declared evidence rules are satisfied, not that the software is flight-safe. The side panel shows full candidate source and content identity. The matrix lists requirement revisions, test/fault links and blockers. Filter **Show** changes only the displayed rows; summary/exports still include the whole package. Latest-test cards explain whether a result was accepted and why.

Try `Newer failing attempt`: an old pass still exists in JSON, but the latest failure blocks readiness. Try `Changed requirement revision`: the same test pass is stale. Try `Missing fault coverage`: a passing test does not cover a declared fault obligation. `Mixed evidence problems` also shows a release source mismatch. Download JSON for a full report, CSV for review, script-free HTML for a readable archive, or **Replay input** for the CLI.

To use your own **nonsensitive** bounded declaration, copy `examples/recorder.json` outside the checkout, edit its explicit links/revisions/results, and run `python -m evidencekit export --input <file> --output <new-report>` or `gate --input <file>`. Keep original source and actual test evidence for independent human review. Never substitute a manually edited pass label for a real test. There is no arbitrary test runner in this kit; the authored demo capture is fixed and separate.

Optional `--history <private.sqlite3>` stores full JSON reports locally and unencrypted. Immutable SQL triggers prevent accidental update/deletion through the app, **not a malicious file owner**. Duplicate identities are idempotent; at 100 reports choose a new path. No automatic deletion/retention policy exists. Back up private histories under your normal policy; do not commit them. Exports refuse existing files; choose a new filename.

If evidence is unavailable, check the owned local service console, rebuild web assets for source use, and reevaluate. No partial or previous green result is shown after an error. If a port is busy, use the default random port or another free port; do not terminate unrelated applications. If a source environment fails setup, check supported Python/Node versions and writable TEMP path. Do not change Docker or disable endpoint/browser security. Browser downloads may need your usual browser permission; no popup windows are used. Keyboard navigation, native labels, skip link, screen-reader status and horizontal table scrolling are supported. Documentation and issue links intentionally open GitHub only when clicked.
