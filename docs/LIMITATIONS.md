# Honest limits

Author: Jason Stys.

This is synthetic civilian systems-engineering education. It is not NASA/agency-certified, flight-qualified, nuclear/weapon guidance, hardware control, formal verification or authorization to release safety-critical software. Traceability can expose declared gaps but cannot discover omitted requirements, false input statements, deficient test assertions, unmodeled faults or a fabricated test history. A signature authenticates origin, not technical adequacy.

JSON fixtures use deliberately fictional digests and fixed timestamps. Release digest is recorded metadata, not a binary fetched and verified by the graph engine. Source equality is not compiler reproducibility. Requirements/test/fault links are explicit; no natural-language interpretation, requirement decomposition or automatic coverage proof occurs. Revisions are integers, not a full change-management system. There are no waivers, approvals, electronic signatures or role-based access controls.

The SQL cross-check verifies requirement verdict agreement, not independent correctness of every title, report field, identity hash or upstream declaration. It uses the same validated source package, so common input mistakes can affect both evaluators. Python and SQL algorithms have different formulations but are maintained together. Human-reviewed mutation fixtures and randomized properties strengthen, not prove, correctness.

Schema 1 has bounded nonempty collections. Browser scenarios are finite and read-only; custom packages and JUnit use the CLI. The JUnit adapter is one fixed reviewed suite, not a universal test-runner importer. No arbitrary source compilation, user command execution, telemetry ingestion, cloud hosting or real mission connection exists. This is intentional containment.

Portable apps are unsigned, architecture-specific desktop ZIPs built/tested on hosted runner OS versions. No mobile installer, code signing, notarization, OS-store listing or compatibility guarantee for other versions. Local disk exports/history are unencrypted and user-owned. Deleting/modifying them outside the app is possible. No retention cleanup is automatic. CodeQL, dependency audits and tests are useful point-in-time checks, not a guarantee of zero vulnerabilities.
