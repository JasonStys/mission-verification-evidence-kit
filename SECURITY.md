# Security boundaries

Created by Jason Stys. This local educational application is not an Internet service or a mission control system. Report suspected vulnerabilities privately through [Jason Stys's public GitHub contact profile](https://github.com/JasonStys); do not post sensitive payloads, credentials or actual mission data in issues.

The service binds only IPv4 loopback and validates exact Host, Origin and browser cross-site metadata. Read-only finite GET APIs do not accept user files, arbitrary commands, URLs or uploads. Built static assets are suffix/path allowlisted and resolved within one dedicated directory; hidden/source files and symlink escapes are refused. Restrictive CSP, no framing/forms/objects, no CORS, nosniff, no-referrer, no-store and disabled camera/microphone/location reduce browser exposure. UI strings use text nodes, HTML exports escape text and CSV neutralizes formula-leading text. There are no CDNs, ads, trackers, external models or page-load network services.

CLI JSON/XML files are bounded, regular-file checked, duplicate/reference/type validated and never executed. DTD/entities/ambiguous JUnit outcomes are rejected. SHA-256 is integrity/content identity only. Missing/failed/expired evidence is not inferred successful. Independent SQL mismatch yields no report. Optional local SQLite uses bound parameters, closes connections, has immutable-record triggers, and is ignored by Git; it is **unencrypted** and is not an account store or tamper-resistant audit log. Protect files with OS permissions/encryption and avoid sensitive data. A privileged/local malicious process can still read or change local files and interfere with loopback applications. This design does not promise defense against a compromised PC or local denial of service.

The delivery CLI uses a narrow existing release format, no shell, bounded timeout and explicit independently selected identity. It calls installed trusted GitHub CLI verification and fails closed on unavailable/offline/rejected attestations. It does not execute the verified zipapp or treat its own metadata as a trust policy. It is unrelated to flight evidence authenticity. No tokens are stored in this repository or receipts; normal GitHub CLI authentication remains under the user's control.

Dependencies are locked; Actions refs are full-SHA pinned, checkout credentials are not persisted, default token permissions are read-only, CodeQL has only the analysis-write scope it needs, release jobs have only draft-upload scopes. No `pull_request_target`, arbitrary uploaded test execution, Actions artifacts or caches. Portable binaries are unsigned; no elevation, security bypass, auto-install/update, hardware command or silent network service exists. Review [limitations](docs/LIMITATIONS.md), [provenance](docs/PROVENANCE.md) and [release procedure](docs/RELEASE.md).
